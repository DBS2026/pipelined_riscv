RV32I Pipeline Datapath

RV32I Five-Stage Pipeline

Design reference for a reduced 32-bit RISC-V core: the datapath, instruction set, encodings, control signals, hazard handling, module list and test setup. Datapath of the reduced 32-bit core: 23 instructions, full forwarding, lw→sw store forwarding, and branches resolved in EX. Every block is a Verilog module; orange labels give the module name. riscv_top.v only instantiates and wires them. Scroll sideways on narrow screens.

CPI = 1 + (load-use stalls + 2 × taken branches and jumps) ÷ instructions. The pipeline predicts not-taken, so a branch that is not taken costs nothing.

Verification

asm.py assembles a 66-instruction test program and runs it on an instruction-level Python model to produce expected.txt. The self-checking testbench runs the RTL and compares all 32 registers, every data-memory word written, and the number of load-use stall cycles.

CoveredHow
All 23 instructionsEach one executes at least once, with negative operands for the signed ones
ForwardingBack-to-back dependent ALU instructions, from both MEM and WB
Load-use stalllw → add, and lw → sw where the load gives the store address (3 stalls expected)
Store forwardinglw → sw with the loaded value as store data, no stall
Control flowTaken and not-taken branches of each type, a backward loop, jal call and jalr return, with flushed instructions that must not execute
Invalid encodingslui, auipc, sra, sltu, lb, sb and ecall must change nothing
python3 asm.py        # writes program.hex, program.lst, expected.txt
iverilog -o sim tb_riscv.v riscv_top.v alu.v control_unit.v \
         dmem.v imem.v regfile.v hazard_unit.v
vvp sim               # prints *** ALL CHECKS PASSED ***

Result: all checks pass, with 3 load-use stall cycles as expected. Disabling store forwarding, the register-file bypass, the store stall exemption or the NOP decoding each makes the test fail.
